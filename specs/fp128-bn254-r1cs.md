# Canonical q128 arithmetic in BN254 R1CS

This slice constrains `Prime128OffsetA7F7` arithmetic in the BN254 scalar field.
It is a reusable polynomial-evaluation component, not a complete Akita verifier,
transport protocol, or Spartan proof. The source modulus q is derived from the
existing native field definition; the destination is concretely `jolt_field::Fr`.

## Accepted relation and implementation map

`jolt-r1cs/fp128-bn254` exposes `fp128_bn254::Fp128Var`. Its private representation
holds a native variable x, linked Boolean bits, and optional witness-generation
data. `allocate` enforces x's 128-bit decomposition and a 128-bit complement d,
with `x+d=q-1`. Since both are below 2^128 and their sum is below the BN254
modulus r, this proves `0<=x<q` over integers. Canonicality is enforced even when
an adversary replaces the honest assignments.

`multiply` allocates canonical c and k and enforces `ab=c+qk` modulo r. It reuses
the low three bits of those same decompositions. Since q=1 modulo 8, their
residual `a0*b0-c0-k0` lies in [-14,49]. If it is divisible by 8, its quotient t
lies in [-1,6]. Three additional Boolean bits encode s=t+1, and the constraint
`a0*b0=c0+k0+8s-8` establishes divisibility by 8. This small equality also cannot
wrap in r: its residual lies in [-62,57].

Canonical a,b,c,k imply `|ab-c-qk|<q²`. The tested exact moduli satisfy
`4r<q²<8r`, with r odd. The two congruences therefore force integer equality.
For every canonical input pair, the honest quotient is at most q-2, proving
completeness of its canonical range.

`add` allocates canonical c and one Boolean carry k and enforces `a+b=c+qk`.
Its entire residual has magnitude less than 2q<r, so no CRT check is needed.

`jolt-poly/r1cs::evaluate_fp128_bn254` is the first library caller. It evaluates
little-endian coefficients using Horner multiplication and addition over q,
with a variable point. The zero polynomial is constrained to zero. The routine
does not equate source arithmetic with native BN254 arithmetic.

## Assignment, shape and errors

Construct a fresh builder with `None` assignments for the layout walk, or `Some`
canonical integers for the witness walk. Fixed coefficient count produces
identical matrices; witness values do not become matrix coefficients. Missing
assignments fail through `R1csBuilder::witness`. Invalid canonical inputs and
out-of-range variable references return typed errors. Values must be used in
the builder that allocated them; variable indices do not carry builder identity.

Witness generation computes c with the existing native q field. It obtains k
as `(ab-c)/q` in Fr, then checks that the canonical result fits q. This recovers
the integer quotient because the honest quotient is below q<r. This convenience
does not participate in the constraint proof. Witness generation is not
constant-time; no secret-memory zeroization or end-to-end ZK claim is made here.

## Validation and full constraint accounting

Tests use independent `BigUint` arithmetic for boundary products/sums and
polynomial evaluation. They connect the numerical bound to Fr's actual modulus,
exercise the explicit residual-E=r counterexample, mutate completed witnesses,
replace c/k with consistently range-encoded wrong values, and compare unknown
and known circuit layouts. These are soundness regressions, not an independent
proof audit.

Run the intentional diagnostic:

```sh
cargo run -p jolt-poly --example fp128_r1cs_cost --features r1cs -q
```

| Degree-three Horner, including all four coefficients and point | 3,633 | 3,611 | 14,517 |

With already constrained inputs, multiplication adds 521 rows: 516 for canonical
c/k, three Boolean rows, and two congruence rows. Addition adds 260 rows.
There are no assumed lookup gates, uncharged range witnesses, or detached low
bits. The diagnostic counts actual emitted sparse matrices after normalization.
These are circuit sizes, not proof bytes, EVM gas, or measured prover time.

## Remaining comparisons

A two-limb carry implementation is not included, so no CRT-versus-limb speed or
size advantage has been established. Canonicality deliberately uses a simple
complement bound; a gated small-slack construction exploiting q's high bits may
reduce its cost but needs separate review and adversarial tests. Transcript
hashing, sampled challenges, Akita terminal relations and the wrapper's public
statement remain outside this slice.
