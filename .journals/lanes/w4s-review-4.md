## Findings

1. **BLOCKER (score 100) — `crates/jolt-wrapper/src/spartan.rs:256`: the 16-byte public-output
   packer cannot encode the real 28 address challenges.** `pack_challenges` requires each field
   value's canonical representative to fit in `u128`, then `unpack_challenges` maps the word with
   `Fr::from_u128`. The exported `r_ram_addr` and `r_bytecode_addr` coordinates are ordinary
   `challenge()` outputs: `Fr::from_challenge_bytes` reads 16 bytes little-endian, masks three
   bits, and places the result in the high two BN254 limbs (`jolt-field/src/bn254/mod.rs:166-183`).
   Their canonical representatives are almost never below `2^128`, so real inputs fail with
   `ChallengeOutOfRange`; even a word forced through the verifier would decode to a different Fr.
   `spartan_core` uses `Fr::from_u64` fixtures, so its word-tamper test proves binding only for the
   wrong decoder. **Fix:** make the wire word the canonical 125-bit challenge preimage `v` (top
   three bits zero), recover `v` from the challenge field value by the inverse fixed scale, encode
   `v.to_be_bytes()`, and decode it as `Fr(v) * 2^-128`; add a vector generated by an actual inner
   `Blake3Transcript::challenge()` plus a one-bit tamper.

2. **MAJOR (score 75) — `crates/jolt-wrapper/tests/stream_timing.rs:25`: `VerifierCost` is a second,
   hand-maintained verifier model.** The production verifier never increments these counters.
   The test infers operations from proof lengths and constants such as `ec_add = ec_mul - 1`,
   `pairing_pairs = 8`, and a formula-level Fr expression. The Keccak total happens to match the
   present transcript trace and eight pairing pairs are correct, but no check ties the EC/Fr
   formulas to the executed verifier. The journals present 109/108 and 95/94 as current-verifier
   counts despite that drift path. **Fix:** count at the verifier primitive boundary or measure the
   Solidity verifier; until that exists, label EC/Fr figures as estimates and remove exact-count
   assertions/claims.

3. **MINOR (score 50) — `.journals/lanes/w4s-stream-spartan.md:94`: the stated reason for retaining
   all of `HyperKZGProof::v[2]` is wrong.** The fold equations derive
   `P_1(r^2)..P_{ell-1}(r^2)` from the `r`/`-r` rows; only `P_0(r^2)` must remain proof-supplied.
   Keeping that one scalar lets the existing cubic KZG batch open all `P_i` at the same three
   points, with no second witness. This safely removes `ell-1` Fr values, the same
   `32*ell-32` bytes claimed for the extra-witness design. The committed code retains the full
   vector, so this is a byte/spec defect, not a soundness defect. **Fix:** serialize one
   `p0_at_r_squared` scalar, derive the remaining row during verification, and pass the rebuilt row
   to `kzg_verify_batch`.

## Stage C deletion and claim inventory

For Shape G, five factor columns `c_j = (g_j, slot_j)` produce these claims:

```text
Stage A output:
  a = tensor(f_0,...,f_4)
  f_j = P_{g_j}(r_A, bit(slot_j))

Stage B inputs:
  sum_x eq(bit(c_j), x) V(x) = f_j
  V(s) = T(s)

Stage B final check:
  sum_j lambda_j * final_j
    = sum_j lambda_j * eq(bit(c_j), s) * T(s)

Packed opening:
  T(s) = sum_g eq(s_group, g) * P_g(r_A, s_slot)
  point q = (r_A, s_slot)
```

- The five `f_j` values are absorbed as labeled Stage-B input claims before the five
  transcript-derived `lambda_j` coefficients. `prove_batch` emits one eight-round polynomial
  stream and one challenge vector `s` shared by every member.
- The verifier first checks `tensor(f_0,...,f_4) = a`, then uses the same values as the Stage-B
  inputs. No factor claim is omitted.
- Every packed-polynomial term in the final commitment combination is evaluated at exactly
  `q = (r_A, s_slot)`. Its coefficient `eq(s_group,g)` is computed from the verifier-derived
  Stage-B point. Packed commitments were absorbed before `r_A` or `s` was drawn.
- At `37134dbb5`, Stage C received this one claim at `q`, multiplied it by a fresh coefficient,
  and reduced it to a new point. There were no other reduction claims. Directly opening the same
  commitment combination at `q` removes only that redundant reduction.
- Committed Stage A has separate univariate claims
  `S_i(0), S_i(1), S_i(r_i)` for each round. The degree check and BDFG opening discharge them; they
  are not packed-polynomial claims and were not dropped with Stage C.
- Standalone Spartan still opens `W(ry)` in its own HyperKZG call. `Az(rx)`, `Bz(rx)`, and `Cz(rx)`
  are verifier-computed matrix scalars, not PCS claims. The combined wrapper described in the
  journal is **deferred**: no code yet indexes `W` by the T1 row domain, head-aligns Spartan's inner
  sumcheck inside A, or adds W's column to Stage B. That integration must reduce W to the same
  `(r_A,s_slot)` point before sharing the stream opening.

## Keccak outer transcript

```text
initial state = keccak256(label right-zero-padded to 32 bytes)
append(p)     = keccak256(state[32] || round_word[32] || p)
squeeze       = keccak256(state[32] || round_word[32])
round_word    = 28 zero bytes || u32_be(round)
```

- Fr payload: 32-byte canonical big-endian.
- BN254 G1 payload: 32-byte arkworks canonical compressed encoding.
- `Label`: bytes followed by zeros to 32 bytes. `LabelWithCount`: label followed by zeros to 24
  bytes, then `u64_be(count)`; compressed sumcheck rounds count transmitted coefficients, not
  bytes.
- Every append is a separate chained hash, so different append boundaries do not concatenate to
  the same hash input. The generic type codec is not type-injective: a raw 32-byte payload can
  equal a label/Fr/G1 payload, and labels differing only by trailing zero bytes alias. The current
  fixed event schedule and fixed labels remove that ambiguity from this protocol; it must remain
  part of the EVM consensus spec.
- `challenge()` takes the first 16 digest bytes through the legacy 125-bit shifted decoder, not an
  ordinary big-endian integer. `challenge_scalar()` would be big-endian but is unused by this outer
  protocol.
- Message order is complete: round commitments precede `r_i`; disclosed zero/next values precede
  the following round challenge or `rho`; shifted commitment precedes `gamma`; BDFG quotient
  precedes `z`; factor claims precede Stage-B coefficients; every round polynomial precedes its
  challenge; fold commitments precede `r`; all three evaluation rows precede `q`. Final witnesses
  need no later challenge because their pairing equations check them directly.
- Inner hash-table replay remains `Blake3Transcript`; the commit changes only the outer stream
  constructor and adds the Keccak digest alias.

## Pairing equations

Let `C_rho = sum_i rho^i C_i`, `h = beta^(L-1-D)`, and `Z(X) = z0 + z1 X + z2 X^2 + X^3`.

```text
degree: e(C_shift, [1]_2) * e(-C_rho, [h]_2) = 1

BDFG:   e(F + z W', [1]_2) * e(-W', [beta]_2) = 1
        = e(F - (beta-z)W', [1]_2)

HyperKZG:
  e(B-R-z0 W, [1]_2)
  * e(-z1 W, [beta]_2)
  * e(-z2 W, [beta^2]_2)
  * e(-W, [beta^3]_2) = 1
```

The rearrangements match the prior equations. Verification performs no G2 scalar multiplication;
the only scoped G2 multiplication is setup-time construction of fixed SRS points. Stream total:
two degree-check pairs + two BDFG pairs + four HyperKZG pairs = eight.
