# Lane A — BlindFold, jolt-r1cs, HyperKZG and wrapper prior art (read-only audit)

Repo: worktree of a16z/jolt @ origin/main 756bddce3. Line numbers are for that tree unless a branch is named.
"est." marks estimates; everything else is read from source or fixture asserts.

## Verdict (5 lines)

- `jolt_r1cs::R1csBuilder` is a real general sparse-R1CS builder (variables, LCs, products, witness), but has **no gadgets** (bits/range/hash/non-native/points) and no public-input column; the branch `alberto/prover-stack/03-r1cs-extensions` adds exactly those (`FqVar`, `ScalarGadget`, `PoseidonR1csTranscript`).
- BlindFold's Spartan is a correct outer/inner Spartan with verifier-side O(nnz) matrix evaluation (no SPARK), but it is welded to relaxed R1CS (`u`, `E`), Nova folding and Hyrax row commitments — reuse the math (~300 lines), not the crate.
- HyperKZG can be restored as-is from `d80d201d6^:crates/jolt-hyperkzg` — the `CommitmentScheme` core (`setup/commit/open/verify`) did not change since the deletion; only batch-opening defaults did.
- A plain **Spartan + HyperKZG wrapper *verifier*** over arbitrary `ConstraintMatrices` already exists on `alberto/prover-stack/08-wrapper-verifier` (Markos, 2026-06-09), with proof size ≈ 6–8 KB for 2^20–2^24 constraints. What does **not** exist anywhere: the Jolt-verifier-as-R1CS relation, its witness generator, the wrapper prover, and any field-native transcript.
- Every existing transcript (Blake2b, Keccak, and both Poseidons) is **byte-oriented**; G1/G2/GT are absorbed as serialized bytes. There is no Fq-in-Fr gadget on main (branch 03 has a heavy one, est. ≈2k constraints per Fq mul) and no Fq12/GT gadget anywhere.

## 1. jolt-blindfold R1CS tooling

**Builder (general-purpose, reuse as-is).** `crates/jolt-r1cs/src/builder.rs`: `Variable(usize)` with `Variable::ONE = Self(0)` (11-23); `LinearCombination { terms: Vec<(Variable, F)> }` (38-40), `into_sparse_row` dedupes via BTreeMap (107-122); `R1csBuilder { witness: Vec<Option<F>>, a, b, c: Vec<SparseRow<F>> }` (160-165); `alloc / alloc_unknown / alloc_witness / assign / witness()` (183-229); `assert_product(a, b, c)` (231-246), `assert_zero` (248-253), `assert_equal` (255-263), `multiply(a, b) -> Variable` emits `A·B = 1·v` (265-281); `into_matrices` (283-285). Output `ConstraintMatrices { num_constraints, num_vars, a, b, c }` (`constraint.rs:41-47`), `SparseRow<F> = Vec<(usize, F)>` (`constraint.rs:8`), serde with revalidation, `check_witness` (157-167). Column 0 is the constant 1; there is no public-input column — publics are either baked into coefficients (BlindFold) or witness vars pinned by `assert_equal(var, const)` (branch 08 `alloc_public_scalar`).

**Claim lowering.** `crates/jolt-r1cs/src/lowering.rs`: `ClaimSources` (17-25), `SourceValue::{Constant, LinearCombination}` (28-31), `ClaimSourceTable` (51-147, incl. `insert_*_lc`), `lower_claim_expr` (178+), `assert_claim_expr_eq`. Lowers `jolt_claims::Expr` sum-of-products; one `multiply` per extra factor.

**Sumcheck round constraints.** `crates/jolt-sumcheck/src/r1cs.rs`: `SumcheckR1csLayout { input_claim, rounds: Vec<{claim_in, coefficients, claim_out}>, output_claim }` (70-87); `append_sumcheck_r1cs_constraints_for_domain` (150-184); `append_round_constraints` (283-297) emits exactly **2 linear equalities per round**: `round_sum_lc(coeffs) == claim_in` and `polynomial_eval_lc(coeffs, challenge) == claim_out` with the challenge a **constant** (Horner folded into coefficients). Domains: `SumcheckDomainSpec::{BooleanHypercube, CenteredInteger{domain_size}}` (`domain.rs`). Consequence: the BlindFold circuit is per-proof (challenges baked) and almost entirely linear — that is why it is tiny. No hashing is in-circuit.

**BlindFold layout.** `crates/jolt-blindfold/src/r1cs.rs`: `Layout { witness_row_len, stages, final_openings }` (13-17); `build_with_sources` (63-80) — output-claim openings become variables, publics/challenges become constants; `append` (100-159) per stage: `assert_claim_expr_eq(input)`, sumcheck rounds, `assert_claim_expr_eq(output)`; final openings `assert_equal(Σ coeff·opening, evaluation)` (142-157); `allocate_layout` (161-245) pads every coefficient row to `witness_row_len` with `alloc(F::zero())`, claim chain via `alloc_unknown`, dedicated rows for final eval/blinding (248-264); `witness_row_len = next_pow2(max(deg+1, output_row_len, 1))` (266-289).
`protocol.rs`: `BlindFoldProtocol { sumcheck_consistency, committed_output_claims, r1cs: ConstraintMatrices<F>, layout, dimensions, eval_commitments }` (14-21); `BlindFoldDimensions / RowDimensions / WitnessRowLayout { coefficients, output_claims, auxiliary, padding }` (23-47); `build_constraints` uses `R1csBuilder::new()` (434-442); `Layout::dimensions` (446-527): `witness_row_count = next_pow2(coef + output + aux rows)`, `padded_constraints = next_pow2(num_constraints)`, `error_row_len = min(row_len, padded)`, `error_row_count = padded / error_row_len`. Z = [u | W] (`prove.rs:1373 z_vector`); W is a Hyrax grid of `witness_row_len`-wide rows, each Pedersen-committed with ≤ `MAX_BLINDFOLD_GENERATORS = 32` generators (`common/src/constants.rs:34`).
Row width for Jolt: max round degree is `SPARTAN_OUTER_UNISKIP_FIRST_ROUND_DEGREE = 3·10 − 3 = 27` (`crates/jolt-r1cs/src/constraints/jolt.rs:49-66`; domain 10 from `crates/jolt-claims/src/protocols/jolt/geometry/dimensions.rs:15`) → 28 coefficients ≤ 32 → `witness_row_len = 32`.

**Counts, zk_muldiv fixture** (`crates/jolt-verifier/tests/completeness/zk.rs:140-144`; max trace 2^16, `tests/support/verifier_fixtures.rs:598`): `coefficient_rows == 221` (total sumcheck rounds over the 10 ZK stages, `crates/jolt-prover/src/blindfold.rs:10-88`), `output_claim_rows == 15`, `auxiliary_rows == 33`, `eval_commitments == 1`, `error_row_count == 64`.
Derived (est.): `padded_constraints = 64·32 = 2048` → 1025 ≤ num_constraints ≤ 2048; witness rows 221+15+33 = 269 → `witness_row_count = 512` → |W| = 16 384 slots (≈ 8.6k live variables, rest padding); outer sumcheck log2(2048) = 11 rounds (deg 3), inner log2(16384) = 14 rounds (deg 2). Rounds scale with log T (≈ +1 row per stage per doubling of T); constraint count stays O(rounds).

## 2. Spartan inside jolt-blindfold

**Prover** `crates/jolt-blindfold/src/prove.rs`: `OUTER_SUMCHECK_DEGREE = 3`, `INNER_SUMCHECK_DEGREE = 2`, `INNER_SUMCHECK_LABEL = b"inner_sumcheck_poly"` (12-14); `BlindFoldWitness { rows, blindings, eval_outputs, eval_blindings }` (17-22); `BlindFoldRowCommitter` trait (24-132; GPU/backend seam, not a PCS seam); `prove` (153-176) → `prove_with_row_committer` (178-648): commit aux rows (`bf_committed_u/w/e/eval`), sample and commit a random satisfying relaxed instance (`bf_random_*`), commit error rows and Nova cross-terms (`bf_cross_e`), fold challenge (`RelaxedInstance::fold`, `relaxed.rs:35-94`, via `Com::linear_combine`), `Label(b"bf_spartan")`, `tau = challenge_vector(log2(error_row_count·error_row_len))`; `prove_outer_sumcheck` (805-907) over `eq(τ,x)·(Az·Bz − u·Cz − E)`; `abc_at_point` (1052-1069); labels `bf_az_bz_cz`, `bf_error_opening/blind`; inner claim `ra·(az − pub.a) + rb·(bz − pub.b) + rc·(cz − pub.c)` with `public_column_contributions(&row_weights, 0, folded_u)` (600-604); `prove_inner_sumcheck` (913-986) over `L_w(y)·W(y)` where `L_w` comes from `linear_form_project_columns(r1cs, &row_weights, 1, |W|, [ra, rb, rc])` (995-1025, O(nnz)); openings via `VC::open_committed_rows` (Hyrax rows).
**Verifier** `verify.rs`: `verify` (22-48), `folded_instance_from_proof` (56-98), `verify_outer_folded_r1cs` (129-212) — `VC::verify_committed_rows` for E(rx) then `outer.value == eq(τ,rx)·(az·bz − u·cz − e_rx)` (192-199); `verify_inner_folded_r1cs` (419-505) — `public_contributions` (527-537), `compute_l_w_at_ry = r1cs.linear_form_bilinear_eval(&eq_rx, &eq_ry, 1, w_len, [ra, rb, rc])` (539-554; `crates/jolt-r1cs/src/constraint.rs:222-252`). **The verifier evaluates A, B, C at (rx, ry) itself in O(nnz) — no SPARK, no matrix commitments.** Fine natively at ~10k nnz; it becomes the dominant cost only if the wrapper is itself recursed.

**Coupling.** Relaxed `u`/`E`, folding, cross-terms and Hyrax row openings run through every type: `RelaxedInstance { u, witness_row_commitments, error_row_commitments, eval_commitments }`, `BlindFoldProof` (`proof.rs:1-31`, 20 fields, 7 of them commitment vectors), `VectorCommitmentOpening { combined_vector, combined_blinding }` (`crates/jolt-crypto/src/commitment.rs:155-158`). jolt-blindfold is generic over `VC: VectorCommitment` (`commitment.rs:29-150`), **not** over `CommitmentScheme`. Plain R1CS + HyperKZG needs: drop u/E/fold/cross-terms, replace row openings by one `CommitmentScheme::open(W, ry)`, keep the two sumcheck drivers and `linear_form_bilinear_eval`. → **fork the ~300 lines** (prove.rs 805-1025, verify.rs 129-212 + 419-554) or take branch 08's `jolt-wrapper-verifier`, which is exactly that fork (§4). Do not parametrize jolt-blindfold.

**BlindFold proof size, muldiv shape (est.; G1 compressed 32 B, Fr 32 B).** Commitments: 33 aux + 221 random-round + 15 random-output + 33 random-aux + 64 random-error + 1 random-eval + 64 cross-term = 431 G1 ≈ 13.8 KB. Scalars: outer 11·3 + az/bz/cz 3 + inner 14·2 + witness opening 33 + error opening 33 + folded eval output/blinding 2 + their openings 2·33 + random_u 1 = 199 Fr ≈ 6.4 KB. Total ≈ 20 KB for the ZK tail alone (transparent Jolt proof extra). `CompressedSumcheckProof` omits the linear term (deg-3 round = 3 Fr, deg-2 = 2 Fr; `crates/jolt-sumcheck/src/proof.rs`).

## 5. jolt-r1cs in one paragraph

`crates/jolt-r1cs` is first the **uniform per-cycle zkVM R1CS** (`lib.rs:1-48`): `constraints::{rv64 (506 lines: column `[0]` constant, `[1..=35]` inputs, `[36..=37]` product factors; 19 eq-conditional rows + 3 product rows), field_constraints (363; WARNING placeholder rows, unsound), jolt (640; uniskip geometry `jolt.rs:49-66`)}`, `R1csKey` (`key.rs` 687: uniform key with MLE evaluation of the tiny per-step matrices), `R1csSource` / `SpartanChallenges` (`provider.rs` 243). Its general-purpose part is small — `builder.rs` 451, `constraint.rs` 556, `lowering.rs` 488 — an ordinary sparse R1CS builder with witness assignment, `check_witness`, and O(nnz) MLE evaluators (`public_column_contributions` 169-180, `weighted_columns` 182-220, `linear_form_bilinear_eval` 222-252, `matrix_column_eval` 268-289, `matrix_bilinear_eval_columns` 291-333). It can host a large hand-built circuit as-is, but has no gadget library (booleans, bits, range, hash, non-native, curve points) and no public-input abstraction; branch 03 supplies those (`nonnative.rs`, `scalar.rs`).

## 6. Transcript, Poseidon, non-native gadgets

**Selection.** `crates/jolt-transcript` features `transcript-blake2b / keccak / poseidon` all default (`Cargo.toml:15`); types `Blake2bTranscript = SpongeTranscript<Blake2b512, F>`, `LegacyBlake2bTranscript = DigestTranscript<Blake2b<U32>, F>`, `KeccakTranscript`, `PoseidonTranscript<F> = SpongeTranscript<PoseidonSponge, F>` (`lib.rs`). jolt-verifier is generic over `T: Transcript<Challenge = F>`; its `transcript-*` features are empty markers (`crates/jolt-verifier/Cargo.toml:27-29`, no `cfg` use in `src/`). jolt-sdk pins `VerifierTranscript = LegacyBlake2bTranscript<VerifierField>` (`crates/jolt-sdk/src/host_utils.rs:49,67`). → Poseidon is selectable **by type parameter** on prover and verifier together, no feature gate; byte-diff fixtures are Blake2b, so a Poseidon Jolt proof is a new transcript, same size.

**Absorb semantics — all byte-oriented.** `SpongeTranscript::append_bytes = 0x9B || u64 LE len || bytes` (`legacy.rs:262-278`); field elements as 32 big-endian bytes (`legacy.rs:122-129`); `Label` = 32-byte word (149-163), `LabelWithCount` (167-182), `U64Word` (186-194); `challenge()` squeezes **16 bytes → 128-bit challenges even for Poseidon** (`legacy.rs:280-292`, WARNING comment). G1/G2 `AppendToTranscript` = arkworks compressed bytes, 32 B / 64 B (`crates/jolt-crypto/src/ec/bn254/mod.rs:~162-171`); GT = 384 B uncompressed, byte-reversed (`ec/bn254/gt.rs:139-148`). Dory's internal absorbs cross `JoltToDoryTranscript` (`crates/jolt-dory/src/transcript.rs:28-72`): `append_group` = `LabelWithCount(b"dory_group", len)` + compressed bytes, `append_field` = `Label(b"dory_field")` + BE scalar, GT via `append_serde`. `PoseidonSponge` (`poseidon.rs`, 212 lines): light-poseidon width 4 `new_circom(3)`, absorb = length-binding permutation + pairs of 31-byte LE chunks, squeeze 32 B, `ratchet`. So one Fr costs 2 chunks (31 + 1 B) and a permutation per 2 chunks; a G1 point likewise; GT = 13 chunks. In-circuit this needs a byte decomposition of every absorbed element.
The branch's `PoseidonR1csTranscript` mirrors a **different** transcript: legacy `crates/jolt-prover-legacy/src/transcripts/poseidon.rs` (width-3 `hash(state, n_rounds, input)`, 32-byte LE chunks, lines 9-70): an Fr is one absorb (from 32 LE bytes mod order) but group elements are still serialized bytes (G1 compressed = 1 chunk, GT = 12 chunks) and challenges are 32-byte squeezes (128-bit variant `unimplemented!`). **Neither existing Poseidon is field-native** (Fr as one element, points as Fq coordinates); the wrapper needs a new transcript shared by native Jolt prover/verifier and the circuit.

**Fq-in-Fr.** None on origin/main (`grep -rn 'FqVar\|nonnative\|NonNative'` → 0 hits; only the `Bn254GT(Fq12)` type). jolt-field exposes native `Fq` (`crates/jolt-field/src/bn254/mod.rs:258-262`, `lib.rs:116`) for witness generation. Branch 03 `nonnative.rs` `FqVar`: 4×64-bit limbs; `mul` = 16 limb `multiply`s + quotient (`from_checked_limbs`, canonical bound via `assert_limbs_less_or_equal`) + two carry-normalizations (`assert_terms_normalize_to`, 8 carries of `CARRY_BITS = 68`), every range check by **full bit decomposition** (`assert_unsigned_bits`: one boolean constraint per bit). Est. ≈ 2k constraints per Fq mul (8·64 + 2·8·68 + 4·64 + 4·64 booleans ≈ 2.1k). Sound but heavy — thousands of Fq muls in-circuit (any pairing/GT arithmetic) is out of budget without lookups; this is what pushes the branch toward "Fr-side in circuit, pairing native".

**Fq12 / GT gadget.** None on main or any branch. Branch 06 `dory_assist/formulas/{gt.rs 783, miller_loop.rs 1290}` are sumcheck *claim formulas* for an auxiliary Hyrax/Grumpkin assist proof, not R1CS gadgets; branch 07 keeps final exponentiation and the pairing equality native.

## Gaps to build

1. **The Jolt-verifier relation** — absent on every branch. Per stage: sumcheck rounds with variable challenges (2 linear + Horner products per round), claim `Expr`s, in-circuit Fiat-Shamir, stage-8 gamma batching, public-input binding. Transcript cost (est.): ~221 round polys × (deg+1) ≈ 0.8–0.9k Fr + claims + commitments ≈ 1.5k absorbed elements; Poseidon t=3/4 permutation ≈ 240–260 R1CS constraints (pow5 s-box, 8 full + 56/57 partial rounds) → ≈ 0.2–0.4M constraints for FS alone. Dory decision drives everything else: (a) Dory native outside the wrapper — wrapper proves only the Fr side, Dory proof stays (size then bounded below by Dory's proof; lane B numbers); (b) Dory-assist (branch 06/07: Miller loop in an auxiliary Grumpkin/Hyrax proof, final exp + pairing equality native); (c) full in-circuit Dory — Fq12 gadget + Miller loop over `FqVar` at ≈2k constraints/Fq-mul → millions of constraints; not viable in plain R1CS.
2. **Field-native Poseidon transcript** (Fr as one element, G1/G2 as Fq coordinates, GT as 12 Fq) implemented once in `jolt-transcript` and mirrored as an R1CS gadget; Jolt prover+verifier instantiated with it for wrapped proofs. Est. 300–500 lines + vectors.
3. **Challenge width**: `challenge()` = 16-byte squeeze. In-circuit truncation to 128 bits needs a range gadget per challenge; cheaper to give the wrapped Jolt instance full-field challenges (touches `Transcript::challenge` for the new transcript only).
4. **Plain-R1CS Spartan prover** over `ConstraintMatrices` with HyperKZG opening of W (branch 08 has verifier only). Est. 400–600 lines (fork of jolt-blindfold drivers minus u/E/fold).
5. **Key digest + public inputs**: absorb a precomputed digest of (A, B, C) instead of every entry (branch 08 absorbs all); fix the public set (Jolt public IO, program/bytecode commitment, Dory commitments or their digest).
6. **HyperKZG SRS**: main has random `setup(rng)` only; need ceremony SRS loading for |W| up to 2^24–2^28 (branch 05 `setup.rs` `hyperkzg_{k}.srs` format, or import a Powers-of-Tau file).
7. **Gadget library**: booleans, bit decomposition, range, select, `AssignedScalar` — branch 03 (`scalar.rs` 443 + `nonnative.rs` 918) or rewrite the ~200-line subset actually needed.
8. **Witness generator** = instrumented verifier replay (recorder-style, as `crates/jolt-prover/src/recorder.rs` does for ZK) emitting every intermediate in constraint order.
9. **Tests**: shape asserts (constraints/variables), tamper-reject (claim, challenge, opening, public input), serialized-size assert on `WrapperProof`; fixtures from `crates/jolt-verifier/tests/support`.
