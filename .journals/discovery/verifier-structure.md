## 1. Verifier stage map

Machinery (exact). Every stage is ONE batched sumcheck generated by `#[derive(SumcheckBatch)]` (`crates/jolt-verifier-derive/src/lib.rs`): `begin_batch` (lib.rs:566-604) computes each present member's `input_claim`, absorbs it under `b"sumcheck_claim"` (`S/recorder.rs:106-116`), draws ONE `challenge_scalar()` batching coefficient per present member (lib.rs:493-510), and forms `claimed_sum = Σ coeff·claim·2^(max_num_vars − rounds)` (`S/batch.rs:34-72`). The batch then runs `max_num_vars` rounds via `verify_compressed_boolean` (`S/proof.rs:124-141` → `S/verifier.rs:88-132`): per round absorb `LabelWithCount(b"sumcheck_poly", d)` + `d` coefficients (linear term omitted, recovered from `s(0)+s(1) = running`, `crates/jolt-poly/src/compressed_univariate.rs:44-70`), one `challenge()`, `evaluate_with_hint` (2d−1 Fr mults). Members with fewer rounds are tail-aligned (`offset = max − rounds`, `V/stages/relations.rs:198-227`); precommitted cycle phases are head-aligned (offset 0). Tail: `derive_opening_points`, `expected_final_claim = Σ coeff_m · expected_output_m` (lib.rs:857-946), equality check, then output claims absorbed under `b"opening_claim"` (aliased openings skipped, `relations.rs:146-160`). Stages 1 and 2 first run a uni-skip round: a FULL (uncompressed) 1-round sumcheck over a `CenteredIntegerDomain` (`V/stages/uniskip.rs:137-171`; `S/verifier.rs:48-85`), output hard-checked then absorbed as `b"opening_claim"`.

Wire coefficient count per round = actual degree of the batched round polynomial (prover trims trailing zeros, `S/prover.rs:159-169`), not the declared bound. This matters for stages 5 and 6a (below) and for a fixed-shape circuit (§6).

## 2. What the verifier does outside the sumcheck rounds

Per stage, Fr arithmetic between/around the round checks (all counts are estimates unless a line is cited as exact). "Derived" expression factors are re-evaluated at every occurrence (`crates/jolt-claims/src/claims.rs:101-125`, `ops.rs:140-160`, no memoization), which inflates several eq costs by a constant factor.

| Stage | Work | Size | Flag |
|---|---|---|---|

## 3. Dory verification

### 3.1 Jolt's batching (stage 8)
One joint Dory proof per Jolt proof (`proof.joint_opening_proof`, `V/stages/stage8/verify.rs:169, 237`; prover `crates/jolt-prover/src/dory/stages/stage8.rs:247-254` via `HomomorphicBatch::prove_batch`, `crates/jolt-openings/src/schemes.rs:492-529`). RLC with one squeezed γ and powers γ⁰..γ^{N−1} (`challenge_scalar_powers`, `crates/jolt-transcript/src/legacy.rs:82-91`). Joint commitment `PCS::combine` = `DoryScheme::combine` (`crates/jolt-dory/src/scheme.rs:313-323`): `Σ_i γ^i · C_i` as **N independent GT exponentiations** (`ArkFr * ArkGT` = inner Fq12 `Field::pow`, generic square-and-multiply, `D/backends/arkworks/ark_group.rs:244-249`; NOT `cyclotomic_exp`, no multi-exp) + N−1 Fq12 mults. Joint claim `Σ γ^i·claim_i·scale_i`.

Layout: every committed poly is committed in the same grid, `n = total_vars = log_k_chunk + L` (`crates/jolt-prover/src/config.rs:162-183`; asserted `stage8.rs:185`), σ = ⌈n/2⌉ columns-vars, ν = n − σ row-vars (`scheme.rs:242-243`); Dory folds the column dimension so **verifier rounds = σ** (`D/evaluation_proof.rs:391`), constraint ν ≤ σ. Dense T-sized `RdInc`/`RamInc` sit at flat index t (top `log_k_chunk` address vars = 0), one-hot RA chunks (K_chunk×T = 2^4·2^L) at index `k·T + t`, advice/bytecode/program-image block-embedded top-left (`crates/jolt-kernels/src/reference/opening.rs:60-63, 145-186`). So Dory always sees **n = L + 4** for L < 25 (n = L + 8 for L ≥ 25): n = 22/24/26/28, σ = 11/12/13/14 at L = 18/20/22/24 (lane C measured 11 rounds at 2^18 ✓).

Commitments carried: `RdInc, RamInc, InstructionRa×32, BytecodeRa×bytecode_d, RamRa×ram_d` = `34 + bytecode_d + ram_d` → **N = 41** for bytecode_d = 3, ram_d = 4 (`V/proof.rs:103-110`; counts `C/geometry/dimensions.rs:417-419`); +1 per advice commitment, +`bytecode_chunk_count + 1` in committed-program mode. (L ≥ 25: log_k_chunk = 8 → instruction_d = 16, N ≈ 23.)

### 3.2 Dory verifier algorithm (dory-pcs 0.4.2, transparent mode)
Entry `verify_evaluation_proof` (`D/evaluation_proof.rs:320-480`), state machine `DoryVerifierState` (`D/reduce_and_fold.rs:69-113, 632-996`). GT `scale` = generic Fq12 `pow` (`ark_group.rs:197-199`); G1/G2 `scale` = full projective scalar mul (`ark_group.rs:49-51, 122-124`). The verifier never materialises the 2^ν / 2^σ Lagrange vectors — the point is folded scalar-by-scalar (`reduce_and_fold.rs:729-733`); `compute_left_right_vectors` is prover-only.

Pre-processing (online): `e2 = g2_0 · y` — 1 G2 mul (`evaluation_proof.rs:384-387`); point split `s1 = point[..σ]`, `s2 = point[σ..]` zero-padded (`:406-411`); initial state from VMV message `c, d1 = joint commitment, d2, e1` (`:413-423`) — no group ops; the VMV consistency `D2 = e(E1, Γ2_0)` is deferred into the final multi-pairing. Two `VerifierSetup` clones per verify (`:422`, `scheme.rs:304`).

Per reduce round k = σ..1 (`process_round`, `reduce_and_fold.rs:675-737`):

| op | count | lines |
|---|---|---|
| Fr inversions (α⁻¹, β⁻¹) | 2 | 691-692 |
| GT exps (254-bit): `d2^β, d1^{β⁻¹}, C₊^α, C₋^{α⁻¹}; D1L^α, Δ1L[k]^{αβ}, Δ1R[k]^β; D2L^{α⁻¹}, Δ2L[k]^{α⁻¹β⁻¹}, Δ2R[k]^{β⁻¹}` | **10** | 695-714 |
| GT (Fq12) mults | **11** | 695-714 |

| G2 scalar muls / adds | 3 / 3 | 723-726 |
| Fr mults | ≈8 | 703, 710, 732-733 |
| transcript: absorb 12 elements (4 GT, 1 G1, 1 G2; then 2 GT, 2 G1, 2 G2), squeeze β, α | | `evaluation_proof.rs:429-443` |

Setup read per round: `chi[k], delta_1l[k], delta_1r[k], delta_2l[k], delta_2r[k]` (5 GT constants; `D/setup.rs:47-80`, built `:121-172`) — public parameters, not proof data.

Final (`verify_final`, transparent arm `reduce_and_fold.rs:953-991`): Fr inv 2 (`d⁻¹, γ⁻¹`); RHS `C + ht^{s1·s2} + χ₀ + D2^d + D1^{d⁻¹} + D2_init^{d²}` = **4 GT exps + 5 GT mults** (`:961-966`); pairing inputs: `E1 + d·Γ1_0` (1 G1 mul), `E2 + d⁻¹·Γ2_0` (1 G2), `(−γ)(E2acc + d⁻¹s1·Γ2_0)` (2 G2), `(−γ⁻¹)(E1acc + d·s2·Γ1_0)` (2 G1), `d²·E1_init` (1 G1) (`:969-983`); **one 4-pair multi-pairing** `E::multi_pair` (`:985` → `ark_pairing.rs:144-180, 311-320`: single `Bn254::multi_miller_loop` over 4 pairs + 1 `final_exponentiation`); one Fq12 equality. **Zero Fq12 inversions** anywhere (`ArkGT::neg` is never called; ZK arm's subtraction is a conjugation).

Totals as f(σ): GT exps `10σ + 4`; GT mults `11σ + 5`; G1 muls `3σ + 4`; G2 muls `3σ + 4` (incl. `e2`); pairings `4 Miller loops + 1 final exp` (one multi-pairing); Fr inversions `2σ + 2`; Fr mults ≈ `8σ + 6`. Cost note (estimate): one generic-pow GT exp ≈ 254 Fq12 sqr + ≈127 Fq12 mul ≈ 300 Fq12-mult-eq ≈ 16k Fq mults ≈ one pairing — GT exps dominate. ZK arm adds +5 GT exps, +5 GT mults, +3 G1, +3 G2 (`:883-948`, `verify_sigma1_proof` `:548-577`).

Deserialization cost (paid before verification, not in the tables): `DoryProof` is `deserialize_compressed` with `Validate::Yes` (`crates/jolt-dory/src/types.rs:96`) → every proof GT element runs `PairingOutput::check = pow(r)` (`A/ec/src/pairing.rs:191-199`) = **6σ + 2 extra 254-bit Fq12 exps**; every G2 runs on-curve + `[6x²]P == ψ(P)`; each of the N commitments (`Bn254GT::deserialize`, `gt.rs:208-250`) costs 1 conjugation-mult + 1 `pow(r)`. ⇒ ≈ `6σ + 2 + N` GT exps of subgroup checks — comparable to the whole online verification; a wrapper must decide whether these membership checks are trusted, native, or in-circuit.

Proof structure (`D/proof.rs:23-61`, `D/messages.rs:10-111`; wire order `ark_serde.rs:324-376`): VMV `c: GT, d2: GT, e1: G1`; `num_rounds: u32`; σ × `FirstReduceMessage {d1_left, d1_right, d2_left, d2_right: GT; e1_beta: G1; e2_beta: G2}`; σ × `SecondReduceMessage {c_plus, c_minus: GT; e1_plus, e1_minus: G1; e2_plus, e2_minus: G2}`; `final_message: Option<{e1: G1, e2: G2}>` (Some in transparent); `nu, sigma: u32`; 5 zk `Option`s (feature `zk` is compiled in via `Cargo.toml:282-288`; all `None` = 1 byte each). Elements: **GT = 6σ + 2, G1 = 3σ + 2, G2 = 3σ + 1**; bytes (compressed; GT is 384 B regardless) = **914 + 2592σ** inner, 917 + 2592σ on the bincode wire.
